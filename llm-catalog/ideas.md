# Ideas

- `Api` still names cox's wires (`Responses`, `Chat`, `Jev`). A neutral effort policy (a table the host supplies) would suit aulo better, but changes the public enum, so it needs a cox migration.
- A `models.toml` refresher in this repo, so aulo can update the rows without going through cox's vendor pipeline.
- Overlap with `llm-openai` (branch `t1-3-llm-openai`, `llm_openai::config`): its `ProviderModel` (id, context_window, reasoning_effort, images) is a subset of this crate's `ModelEntry` (which adds `display_name` and `efforts`); its `Capabilities` (reasoning_effort_param, images, `declared_by`) is a subset of this crate's `Capabilities` (which adds `tools` and `adaptive_thinking`); its `Capabilities::chat_effort` is `effort_for(Api::Chat, ..)`. Both copies come from cox and are identical in meaning, so a host would hold two parallel types for one model entry. Proposal: move `ModelEntry` (under the name `ProviderModel` if cox's name is kept) and `Capabilities` into `llm-wire`, which both crates already depend on and which already carries serde and schemars, then re-export them from `llm-catalog` and `llm-openai`. `llm-catalog` itself is the wrong home: depending on it would pull the embedded price tables and the TOML parser into every wire. `Transport` stays in `llm-openai`/`llm-http`. `effort_for` stays here and `chat_effort` can call it or be dropped. Needs a decision before T1.6 and the llm-openai adoption task.
